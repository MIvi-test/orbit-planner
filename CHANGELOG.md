# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Записи пишутся
для пользователя и администратора сервиса: что изменилось в поведении, данных,
запуске. Внутренняя кухня — в `FIXES_TRACKER.md` и ADR.

Каждый MR добавляет строку в раздел «Не выпущено» (правило —
`IMPLEMENTATION_PLAN.md` §2.3). Идентификаторы пунктов — из `FIXES_TRACKER.md`.

## [Не выпущено] — ветка `fix` от `develop`

### Добавлено
- Экран разметки технологий задачи с источником, подтверждением и пересчётом
  плана (DA-01).
- Календарь ставок орбит по спринтам и датированные подтверждённые
  квалификации; план и профиль инженера учитывают новые записи (DA-14/25).
- Архив исходных файлов загрузок и прежних снимков KPI/расписания,
  скачивание редакций, ключ повторного запроса и проверка одинаковых файлов
  разных спринтов (DA-44, частично).
- Сравнение greedy/atomic и перебор порядков инициатив на малых входах;
  повторная упаковка atomic (DA-12, частично).

### Исправлено
- Время создания прогона, горизонт факта и время ответа API подписаны отдельно;
  карточка инженера показывает фонд, назначения и свободные часы по спринтам;
  Гант различает работу, ожидание и выполненный факт (DA-48).

Автоматическое переигрывание более поздних отчётов после коррекции и
доказательство глобального оптимума плана пока не реализованы.

### Исправления аудита (приём `fix/audit-integration`, волна 1)

Группы и идентификаторы — `FIXES_TRACKER.md`.

- **Остаток работ и SP.** ETC отдельно от потраченных часов; без ETC остаток =
  смета − факт и помечен «не подтверждён», `ETC_REQUIRED` — только когда у
  незакрытой задачи не осталось остатка (DA-05, B-6); остаток SP по подтверждённому
  прогрессу (DA-06); обёртка «символическое назначение 0.01 ЧЧ» убрана.
- **Факт спринта.** Валидация дат и NaN/Infinity, дат и заголовков (DA-17/18/20/21);
  отчёт закрывает спринт только если он полный и подтверждён (DA-19); исправление
  прошлого спринта в интерфейсе (DA-49); исторические отклонения не меняются от
  будущего факта (DA-37).
- **Публикация плана.** Данные и план — одна транзакция (DA-40), блокировка писателей
  в БД (DA-41), приёмка блокирует публикацию, инварианты по неизменяемому снимку
  спроса (DA-45), статус завершённого плана и выбор прогона (DA-42/43), метрики
  различают прогноз и факт (DA-46).
- **Планировщик.** Несколько орбит в одном назначении (DA-08), режим зависимостей
  в проверке (DA-09), живой граф по факту (DA-10), симуляция следующего PI не
  отменяет задачи (DA-13), спрос следующего спринта, каскадные алерты и прогноз
  даты вне квартала (DA-33/34/35), точность `v_plan_diff` (DA-36), остаток против
  остатка фонда (DA-39).
- **Данные.** Блокировка плана при ошибках качества, типы ячеек, цикл графа,
  авторитетная смета (DA-22/23/24/26); канонические навыки (DA-02);
  требования технологий к задачам с подтверждением (DA-01); критичность навыка
  по спросу (DA-03); сценарий отсутствия инженера (DA-04); цели и подтверждённые
  результаты (DA-15).
- **KPI.** Неопределённые значения вместо ложных 100%/0% (DA-28); знаменатель
  Say/Do из снимка базовой линии (DA-31).
- **Интерфейс.** Полная загрузка страниц витрин (DA-47), исторический срез по
  выбранному прогону (DA-38), пояснение раздельных бюджетов SP и часов (DA-07).
- **Документация** выровнена под текущий календарь и модель (DA-50).

### Безопасность и доступ (волна 2)

- **S-1.** Исправлено чтение любых файлов сервера через `/%2e%2e/…` в раздаче
  статики: путь раскрывается до проверки границы. Тесты на `..`, `%2e%2e`,
  `..%2f`, нулевой байт.
- **S-2.** Вход по токену и три роли (`viewer`, `planner`, `admin`): без токена
  API отвечает `401`, роли не хватает — `403`, подбор токена — `429`. Экран входа,
  роль в шапке, ограничение действий в интерфейсе. Пользователи —
  `tools/manage_users.py`; журнал `audit_log`; автор загрузок. **Для обновления:**
  задайте `PI_PLANNER_ADMIN_TOKEN` в `.env` (иначе `docker compose` не стартует);
  `run.sh` создаёт токен сам. Для доверенной машины — `PI_PLANNER_AUTH=off`.
- `/api/health` и `/api/version` без токена отдают минимум (без адреса базы и версий).
- Заголовки безопасности и CSP отдаёт само приложение; зависшие соединения закрываются
  через 30 с; нечисловой `Content-Length` — `400`, а не `503`.
- Новый маршрут `GET /api/me` (ADR-018: набор маршрутов расширен), миграция `0065`.

### Модель планирования (волна 3)

- **Рефакторинг:** `app/planner.py` разбит на пакет `app/planner/` (поведение не менялось:
  результат идентичен в 40 комбинациях режимов и спринтов).
- **DA-09, ADR-028:** режим зависимостей по умолчанию — `finish_start` (блокируемая стартует
  после *конца* блокирующей); `start_start` включается явно.
- **DA-07, ADR-029:** часы и SP размещаются вместе — спринтов «с SP, но без людей» и наоборот
  больше нет; задача, у которой SP больше ёмкости спринта, растягивается минимум на два спринта.
- **DA-27, ADR-030:** пересчёт учитывает закрытые спринты текущего квартала в скорости команд;
  ёмкость каждого прогона сохраняется (`plan_team_capacity`), экран «Профили» показывает её
  основание; ETL предупреждает об устаревшей и тонкой истории (`TEAM_HISTORY_STALE/THIN`).
  Миграция `0066`, новые витрины `v_team_velocity_observed`, `v_task_done_sprint`.
- **DA-16, ADR-031:** причины переноса строятся из журнала той же проверки совместной выполнимости; новая причина `GRAPH_HORIZON`; конкуренты называются с местом в очереди без ложных «более приоритетных». Миграция `0067`.
- **DA-25:** справочник ролей включает роли из профилей инженеров (сотрудник с ролью вне сметы больше не теряется); пустая роль — блокирующая ошибка.
- **Загрузка датасета ускорена с ~17 с до <1 с** (ETL обращался к читалке формул на каждое число).
- **DA-11, ADR-032:** явный бизнес-приоритет инициативы (✎ на Ганте, `POST /api/initiatives/priority`, миграция `0068`) и стратегии приоритета `max` / `task` / `weighted` / `completion_first` (`--priority-strategy`); пересчёты наследуют режимы базового прогона; `tools/compare_priority.py` сравнивает стратегии. На выданных данных все стратегии дают один состав квартала.
- Демо-файлы `demo/*.csv` теперь сообщают `completed_sp` по плану.
