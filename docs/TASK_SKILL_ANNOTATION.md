# Подтверждение технологий задачи

Связи задачи с технологией в исходном Excel нет. До ручной проверки сочетание
задачи и роли имеет статус **не подтверждено**. План может использовать инженера
этой роли, но `plan_runs.params.skill_validation` и предупреждение
`SKILL_REQUIREMENTS_UNVERIFIED` не позволяют считать это проверенным совпадением стека.

Для ручной разметки откройте **Роли → Требования задачи к стеку**. Выберите
сочетание задачи и роли, укажите технологии и источник (ссылка или цитата),
при необходимости отметьте «Подтверждаю полный набор требований» и сохраните.
Сохранение атомарно обновляет требования и пересчитывает план. Просматривать
список можно с ролью `viewer`; сохранять — с ролью `planner` или `admin`.

Те же операции доступны через `GET/POST /api/tasks/skill-review`. Тело POST:
`task_id`, `role_id`, `skill_ids` (массив ID), `source_text`, `confirmed`,
`reviewed_by` (при отключённой авторизации). Для аварийной ручной разметки
можно использовать SQL. Найдите `task_id`, `role_id` в `task_role_estimates`
и `skill_id` в `skills`; сохраните источник, проверившего и время. Если
технология нужна, сначала создайте черновик и связь:

```sql
BEGIN;
INSERT INTO task_role_skill_reviews
    (task_id, role_id, status, source_text)
VALUES ('TASK-1', 1, 'proposed', 'ссылка на карточку задачи и цитата требования');
INSERT INTO task_role_skill_requirements
    (task_id, role_id, skill_id, source_text)
VALUES ('TASK-1', 1, 42, 'Kafka указана в карточке задачи');
COMMIT;
```

После проверки подтвердите полный набор требований этой роли:

```sql
UPDATE task_role_skill_reviews
SET status = 'confirmed', reviewed_by = 'имя проверившего', reviewed_at = now()
WHERE task_id = 'TASK-1' AND role_id = 1;
```

Подтверждённая запись без строк в `task_role_skill_requirements` означает, что
технологических ограничений для этой роли нет. Это отдельное решение, а не
отсутствие данных. Планировщик допускает к подтверждённой работе только инженеров,
у которых есть **все** требуемые навыки; при отсутствии подходящих переносит задачу
с причиной `SKILL_UNAVAILABLE`. Навыки пока заявлены сотрудниками, поэтому
проверка удостоверяет совпадение разметки и профиля, а не фактический уровень владения.
