# UI_DESIGN — оформление интерфейса

Этот документ фиксирует, как выглядит интерфейс: темы и палитры, шрифты, каркас,
типовые блоки и правила. Что показывает каждый экран и из каких витрин берутся
данные — в [UI_SPEC.md](UI_SPEC.md).

Стек: React 19, Vite, TypeScript, **Mantine** (таблицы, формы, выпадающие панели,
загрузка файлов), иконки `@tabler/icons-react`. Гант — CSS grid, звёздная карта —
собственный SVG. Сторонних библиотек графиков нет.

---

## 1. Идея

Квартал — почтовый маршрут: шесть спринтов, шесть пунктов, задача идёт по ним со
статусом. Идентификаторы задач (`ONK-2475`, `DB-202`) читаются как трек-номера,
поэтому для них используется моноширинный шрифт: это смысл, а не украшение.

Пользователь — руководитель разработки или ресурсный менеджер. Его вопрос не
«красиво ли», а «что не влезло и почему». Поэтому объяснение решения — полноправный
элемент экрана, а не подпись мелким шрифтом.

Шесть колонок спринтов — несущая сетка интерфейса: одна и та же на плане, рисках
и графике выполнения спринтов. Остальное оформление спокойное.

## 2. Каркас

```
┌────────────────────────────────────────────────────────────────────────┐
│ PI-Planner  ☀ ▾     [PI-сценарий]  [Прогон]  [PI]  ✓ API  имя  роль  ⊗ │ ← шапка, 60 px
├───────┬────────────────────────────────────────────────────────────────┤
│ ▤ Сводка       │                                                       │
│ ⇪ Загрузка     │                                                       │
│ ▦ План         │   содержимое экрана на всю доступную ширину           │
│ ⚠ Риски        │                                                       │
│ ✦ Звёздная     │                                                       │
│ ◔ KPI          │                                                       │
│ ☰ Роли         │                                                       │
│ ☺ Профили      │                                                       │
│ ⌕ Данные       │                                                       │
│ «              │                                                       │
└────────────────┴───────────────────────────────────────────────────────┘
```

**Боковое меню.** Девять разделов: Сводка, Загрузка, План квартала, Риски,
Звёздная карта, KPI, Роли и ёмкость, Профили, Данные. У каждого своя иконка. Меню
сворачивается кнопкой внизу до одних иконок (64 px вместо 250 px); иконки при этом
остаются на тех же местах и не меняют размер, исчезает только подпись, а название
показывается во всплывающей подсказке. Состояние запоминается в браузере.

**Шапка.** Слева название продукта с подписью «ПочтаТех» и кнопки темы. Справа
по порядку: выбор PI и сценария, выбор прогона, границы PI (только на широких
экранах), состояние API, имя пользователя с цветной плашкой роли и кнопка выхода
(крест в круге, при наведении краснеет).

* **Выбор прогона** показывает коротко («Прогон 1, спринт 0»); подробности (текущий
  ли, итог, стек не подтверждён) — в раскрывающемся списке. У исторического
  прогона рамка поля жёлтая.
* **Состояние API** — одна иконка: зелёная галочка в круге, красный треугольник
  с «!» при недоступности, серая — пока идёт проверка. Подробности в подсказке.
* **Роль** — плашка: администратор фиолетовая, планировщик синяя, просмотр серая.

**Ширина.** Содержимое занимает всю ширину рабочей области без искусственных
ограничений; блоки описаний ограничены по ширине только ради читаемой длины строки.
Интерфейс рассчитан на настольные экраны от 1280 px.

## 3. Темы

Тема = **палитра** × **режим** (светлый или тёмный). Режим переключает кнопка
☀ / ☾ в шапке. Палитру выбирают в выпадающем списке из цветных кружков рядом с этой
кнопкой (половина кружка — фон, половина — акцент; название темы показывается во
всплывающей подсказке). Выбор запоминается в браузере; по умолчанию —
**«Стандартный»** в тёмном режиме.

| Палитра | Светлый режим | Тёмный режим |
|---|---|---|
| Стандартный | белая, акцент тёмно-синий | тёмно-синяя, акцент голубой |
| Розовый | розовая, акцент малиново-розовый | приглушённо-розовая на сливовом фоне |
| Кровавый | розоватая с красным акцентом | почти чёрная красная |
| Фиолетовый | белая с тёмно-фиолетовым акцентом | тёмно-фиолетовая |
| Империум | пергамент с золотом и ультрамарином | металл с золотом, зелёным «экраном» и огненно-красным |

Устройство: Mantine знает только светлую и тёмную схему, поэтому палитра задаётся
атрибутом `data-app-theme` на `<html>` (`pinkie`, `dracula`, `violet`; у стандартной
его нет), а цвета для каждого сочетания палитры и режима переопределены в
`web/src/theme/tokens.css`. Выбор палитры хранится в `appTheme.ts`.

### 3.1. Токены

Каждая тема задаёт один и тот же набор переменных, поэтому таблицы, диаграммы и
SVG звёздной карты меняются вместе с компонентами Mantine.

| Токен | Назначение |
|---|---|
| `--ink` | текст, заголовки |
| `--paper` | фон страницы |
| `--surface` | таблицы, панели, полосы задач |
| `--line` | границы, сетка |
| `--muted` | служебный текст, подписи |
| `--stamp` | срыв, ошибка |
| `--wax`, `--wax-text` | сдвиг, предупреждение (заливка и текст) |
| `--route`, `--route-text` | выполнено, в норме (заливка и текст) |
| `--accent2`, `--accent2-bg` | второй цвет темы: плашки команд |
| `--void`, `--field`, `--star`, `--orbit`, `--flare`, `--ember`, `--bloom` | палитра звёздной карты |
| `--sm-bg0/1/2`, `--sm-core0/1`, `--sm-dot`, `--sm-muted`, `--sm-border` | фон, ядра, звёзды и рамки карты |

Стандартная светлая палитра: `--ink #14213D`, `--paper #EDF0F3`, `--surface #FFFFFF`,
`--line #D5DBE2`, `--muted #5A6472`, `--stamp #C1121F`, `--wax #E3B23C` (текстом —
`--wax-text #8A6212`), `--route #2A9D8F` (текстом — `--route-text #1E7268`).
Контраст этих пар к `--paper` измерен: `--ink` 13.96, `--muted` 5.24, `--stamp` 5.44,
`--route-text` 5.01, `--wax-text` 4.79 — проходят AA для основного текста.
`--wax` и `--route` для текста непригодны: только заливки, линии и точки.
Контраст остальных палитр не измерялся.

Стандартная тёмная: `--paper #0B1020`, `--surface #141B2E`, `--ink #E8ECF5`,
`--line #33415B`, `--muted #A9B5CC`.

### 3.2. Цвета состояния

Цвет никогда не единственный носитель смысла: рядом всегда слово или значок.

| Цвет | Значение | Где |
|---|---|---|
| красный | плохо: ниже нормы, есть блокирующие проблемы, срыв | плитки сводки, риски |
| жёлтый | внимание: есть отклонения | плитки, алерты |
| зелёный | в норме | плитки, KPI |
| серый | нет данных | плитки |
| акцентный синий | без оценки: просто счётчик, норма не задана | плитка «Задач в квартале» |

Границы нормы KPI приходят из базы (`target_min`, `target_max`), во фронте они не
зашиты. Правила окраски плиток сводки — правила интерфейса, а не требование
заказчика:

| Плитка | Красная | Жёлтая | Зелёная |
|---|---|---|---|
| KPI | значение ниже `target_min` больше чем на 20% | вне нормы, но не так сильно | в норме |
| Рисков в прогоне | есть хотя бы один красный риск | есть любые другие риски | рисков нет |
| Вопросов к данным | есть блокирующие находки | есть открытые находки | открытых нет |
| Задач в квартале | не красится: норма не задана | | |

Легенда на сводке показывает значения цветов.

### 3.3. Тема «Империум»

Опциональная палитра в стиле научно-фантастической военной эстетики; светлый
(«пергамент») и тёмный («металл») режимы. Включается иконкой аквилы в шапке (повторное
нажатие возвращает прежнюю палитру) или кружком в списке тем. Это только оформление:
данные, API и хуки не меняются.

* **Материалы.** Зерно металла (SVG-фильтр), панели со срезанными углами
  (`clip-path`), золотые клёпки по углам, кнопки с фаской; `hover` — золотая кромка,
  `active` — «вдавлена», `focus` — чёткое кольцо.
* **Шрифты.** Заголовки и меню — Oswald капсом с разрядкой, служебное и цифры —
  JetBrains Mono, таблицы и текст — Golos Text без декора.
* **Шапка.** Эмблема (аквила, шестерня и череп — собственный рисунок) и подпись
  «PI-PLANNER · ИМПЕРИУМ ПЛАНИРОВАНИЯ»; вместо значка API — «Маяк Варпа»
  (`WarpBeacon`): трон светится при загруженных данных, пуст без данных, погас с
  красной лампой при недоступном API.
* **Состояния.** Ошибки — панель «Гнев Императора» с типом (`ЕРЕСЬ В ДАННЫХ`,
  `ВАРП-БУРЯ`, `НАРУШЕНИЕ ЛИТАНИЙ ПЛАНА`) и исходным текстом, `problems` построчно
  моноширинным шрифтом. Успех — панель «Ультрамарины». Уведомления — терминал
  «Дух машины» с типом словом. Загрузка — `ServitorLoader` (сервочереп, шестерня,
  циклические подписи); скелетоны получают вид экранной сетки.
* **Подписи.** Словарь `imperiumLabels.ts` заменяет названия разделов и заголовки
  главных экранов (Загрузка → «Подношение Свитков», План квартала → «Крестовый
  Поход Квартала», Риски → «Знамения Ереси», Звёздная карта → «Астрономикон», KPI →
  «Литании Доблести» и так далее). Идентификаторы, числа, единицы и даты не
  переименовываются. В подвале — короткие оригинальные «литании».
* **Звёздная карта.** За картой рисуется схема Солнечной системы (орбиты, Терра, Марс
  в виде шестерни, пояс астероидов, линии Варпа); логика и раскладка не меняются; в
  легенде подписи «НЕЗАМЕНИМ», «СТОИТ», «ПОД ЗАЩИТОЙ».

## 4. Типографика

Три семейства, у каждого своя задача:

* **Golos Text** — основной текст и интерфейс (кириллица родная);
* **Manrope** — заголовки, названия блоков и крупные числа;
* **PT Mono** — только идентификаторы (задач, инженеров, инициатив), часы, SP и
  числовые колонки, где важно выравнивание. Числа в таблицах —
  `font-variant-numeric: tabular-nums`.

Шрифты хранятся в самом приложении (пакеты `@fontsource`, подмножества cyrillic и
latin) и отдаются с того же адреса: политика CSP страницы запрещает внешние
стили и шрифты, интернет не нужен.

**Масштаб.** Размеры Mantine заданы в `rem`, а размер корня зависит от ширины окна:
`clamp(18px, 0.6vw + 9.5px, 26px)` — около 18 px на ноутбуке, около 21 px на
1920 px, не больше 26 px. Весь интерфейс масштабируется вместе с корнем.

```
38 px  800  заголовок экрана (h1)
30 px  800  заголовок экрана (h2)
21 px  700  заголовок блока (h3)
17 px  700  подзаголовок (h4)
```

Длина строки текста причин — до 80 знаков.

## 5. Типовые блоки

| Блок | Что это |
|---|---|
| Плитка сводки | число одного размера, мелкая приписка рядом («из 37», «%»), подпись сверху в две строки, подсказка снизу; цветная полоса слева и лёгкая заливка по состоянию; вся плитка кликабельна и при наведении приподнимается |
| Легенда цвета | строка «Цвета:» из чипов с цветной точкой; пояснение в подсказке |
| Строка «подпись — значение» | сетка из двух колонок с пунктирным разделителем сверху; для фактов KPI, разбора алерта, цели и результата |
| Блок KPI | заголовок, формула в пунктирной плашке, строки фактов, затем круги |
| Карточка риска | рамка со цветной полосой слева по уровню, тип риска плашкой справа, строки разбора |
| Плашка команды | скруглённый прямоугольник второго цвета темы (`.team-chip`) |
| Отметки времени | «Расчёт плана» (синяя пунктирная рамка) и «Ответ API» (бирюзовая): это разные моменты, и они оформлены по-разному |
| Боковая панель | разделена на блоки в рамках; заголовок блока выделен шрифтом и линией |
| Текстовая ссылка | подчёркивается при наведении; кликабельные плитки и ссылки всегда меняются при наведении |

**Приёмы, которые несут смысл:**

| Приём | Что кодирует |
|---|---|
| Шесть колонок спринтов | сетка квартала; одинакова на плане, рисках и KPI |
| Круглый штемпель KPI | **тонкое кольцо — прогноз, залитая дуга — факт**; засечки — границы нормы |
| Деления внутри полосы задачи | доли Story Points по спринтам |
| Штриховка сегмента назначения | заём инженера у другой команды |
| Пунктирная линия | задача перенесена в следующий PI |
| Ромб на карте | совместитель на двух орбитах |

**Таблицы.** Заголовки колонок выровнены, у колонок с числами — по правому краю.
В таблице плана заголовок спринта состоит из жирного «Спринт N» и дат под ним,
у задачи — номер жирным и описание под ним на две строки.

**Заглавные буквы.** Подписи, статусы, названия колонок и плашки начинаются с
заглавной буквы. Строчная допустима только внутри предложения.

## 6. Экраны

Данные, витрины и поля — в [UI_SPEC.md](UI_SPEC.md). Здесь — только оформление.

* **Сводка.** Ряд плиток с главными цифрами (задачи в квартале, три KPI, риски,
  вопросы к данным), над ним легенда цвета, ниже таблица «Почему задачи не вошли
  в квартал» с колонкой «Что делать», затем таблицы рисков по типам и дефицита по
  ролям.
* **Загрузка.** Два поля загрузки (датасет и факт), блок создания PI и сценария,
  таблица загруженных отчётов по факту и таблица архива исходных файлов; каждая
  в своей рамке с пояснением. Проблемы файла показываются целиком списком.
* **План квартала.** Легенда «Как читать таблицу» над гантом; в заголовке
  инициативы приоритет, код, название и плашка команды. Клик по строке открывает
  панель с разбором решения.
* **Риски.** Фильтры (уровень, тип, спринт, поиск), сводка по спринтам той же
  сеткой и лента карточек по спринтам; ниже изменения плана, отклонения факта,
  предупреждения приёмки и чувствительность плана.
* **Звёздная карта.** Заполняет весь свой прямоугольник, палитра следует теме.
  Колесо мыши меняет масштаб **только после клика по карте** (Esc или клик вне
  карты выключает), кнопки «+», «−» и индикатор масштаба работают всегда;
  перетаскивание сдвигает приближенную карту. Клик по ядру открывает панель
  команды, клик по точке — панель инженера. Ниже — Bus Factor по компетенциям и
  роли, которых нет в штате.
* **KPI.** Блок «Как читать круги», затем три блока KPI и блок качества плана.
* **Роли и ёмкость, Профили.** Таблицы Mantine; `gap_hh` приходит строкой, знак
  читается как текст. У плашки «Совместители» есть список людей.
* **Данные.** Журнал находок с фильтрами и кнопкой «Выгрузить» (CSV, XLSX, JSON).

## 7. Чего не делать

Каждый пункт — типовой признак сгенерированного интерфейса:

* подписи заглавными буквами сплошь (капслок) над заголовками;
* строки-метаданные, склеенные точками (`A · B · C`): использовать плашки,
  колонки или запятые;
* одинаковые карточки с одной серой тенью под всем подряд;
* градиентные заливки как украшение (исключение — фон звёздной карты);
* появление блоков с затуханием при каждой прокрутке; анимация только в ответ
  на действие (открылась панель, принят файл);
* дефолтный вид Mantine: синий `primaryColor`, тень вокруг каждого блока;
* стрелка `→` в кнопках действий (в текстовых ссылках перехода допустима);
* цвет без слова или значка рядом.

## 8. Тема Mantine

```ts
export const theme = createTheme({
  primaryColor: 'post',
  primaryShade: { light: 8, dark: 6 },
  defaultRadius: 2,
  fontFamily: 'var(--font-text)',
  fontFamilyMonospace: 'var(--font-mono)',
  headings: {
    fontFamily: 'var(--font-heading)',
    sizes: {
      h1: { fontSize: rem(38), lineHeight: '1.15', fontWeight: '800' },
      h2: { fontSize: rem(30), lineHeight: '1.2', fontWeight: '800' },
      h3: { fontSize: rem(21), lineHeight: '1.3', fontWeight: '700' },
      h4: { fontSize: rem(17), lineHeight: '1.35', fontWeight: '700' },
    },
  },
})
```

Акцентная палитра `post` и семантические цвета для каждой темы задаются CSS-
переменными на `:root` и переопределяются под палитру и режим в `tokens.css`: их
читает и SVG звёздной карты, которому палитра Mantine недоступна.

## 9. Тексты

Кнопка называет действие и сохраняет имя до конца: «Загрузить факт спринта 4» →
уведомление «Факт спринта 4 загружен, план пересчитан». Не «Отправить».

Пустые экраны направляют, а не извиняются: «Датасет не загружен. Загрузите
выданный .xlsx — план построится автоматически». Ошибки говорят, что произошло и
что сделать, без «к сожалению».

`reason_text` из базы уже написан по-русски и готов к показу: его не пересказывают
и не сокращают.

## 10. Планка качества

* фокус с клавиатуры виден на всех интерактивных элементах; у иконок есть подписи
  для скринридеров;
* `prefers-reduced-motion` уважается;
* цвет никогда не единственный носитель смысла;
* `numeric` из API приходит строкой, `null` рисуется как «—», а не как 0;
* состояния загрузки показывают скелетоны, ошибки — понятное сообщение.
